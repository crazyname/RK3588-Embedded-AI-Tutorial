## 核心知识精讲

### 数据集质量决定部署上限

训练集数量大不是唯一因素，更重要的是场景覆盖、标注正确、负样本和异常光照/遮挡/小目标等难例。拍摄同一段视频后连续抽帧，邻近帧高度相似，如果随机分到训练/验证，会产生数据泄漏并夸大效果。应按视频、设备、采集场景等组切分，而不是逐帧随机打散。

**你应该能解释：** 保留与训练分布不同的独立测试集，用它衡量真实泛化。

### YOLO 检测标签与 data.yaml

常见 YOLO 检测标注一行包含 class_id x_center y_center width height，四个坐标相对于图像宽高归一化。`data.yaml` 维护 train/val 路径和类别 names。原始坐标换算后必须确保中心点与尺寸落在允许范围内，类别 ID 与 names 顺序一致；空标注、错误类标和漏标都影响训练。

**你应该能解释：** 在训练前随机可视化几十张带框样本，检查类别、坐标和边界。

### 训练指标与实验管理

训练应保存基础超参数如 epoch、batch、imgsz、seed、数据版本和权重初始化来源。验证主要关注 mAP50-95、每类 precision/recall、混淆样本，以及针对实际应用的小目标和遮挡条件的表现。最佳权重应以验证指标选取，再用独立测试集复评。

**你应该能解释：** 将训练日志、曲线、数据划分和 best.pt hash 归档，使下一步模型导出可复现。

## 跟做实验与交付物

### 实验 1：创建小型标注集

选定具有许可的目标检测照片，手工标注至少两个类别，建立 images/train/val 与对应 labels 目录。

**验收证据：** 类别名与 class id 一致，标注框没有明显偏移。

### 实验 2：防泄漏切分

如果数据来自视频，按来源视频或采集日期分组后划分 train、val、test，并检查相邻帧不跨集合。

**验收证据：** 能指出每个集合代表的场景，避免重复片段造成虚高分数。

### 实验 3：执行小规模训练

根据 Ultralytics 版本使用 `model.train(data=..., epochs=..., imgsz=...)`，保存训练/验证指标与最优权重。

**验收证据：** 得到了可追溯的 best.pt、训练配置、失败样例和验证集报告。

## 排查失败场景

### 训练 mAP 很高，部署时常漏检

- 可能原因：验证集与训练集高度相似或部署背景差异大。
- 验证方法：做按场景分组的独立测试并检查难例覆盖。

### 检测框显示到奇怪位置

- 可能原因：标注不是归一化 xywh、类别 id 错或图片与标签文件错配。
- 验证方法：随机可视化原图标注并检查数值范围与目录结构。

## 综合案例分析

**问题：** 你从同一段视频每秒抽 30 帧，随机把 80% 训练、20% 验证，最后 mAP 高达 0.99。能直接宣称工业可用吗？

**推理过程：** 不行。时间相邻的帧内容非常相似，验证结果可能受到数据泄漏影响。应该按视频/摄像头/日期分组切分，并在独立场景验证遮挡、光照和小目标。

**提交材料：** 切分清单、每类样本统计、可视化标注、独立测试集 mAP。
