## 原理详解

### 建立威胁模型

模型加密主要保护模型内容不被轻易直接读取，但不意味着密钥不可获取，也不自动提供设备绑定、签名、安全启动或远程授权。保护级别取决于攻击者是否能拷贝文件、读取内存、取得 root 访问或控制固件。

**判断标准：** 需要把‘模型保密’与‘设备访问控制’分成两个问题。

### 加密模型的版本约束

RKNN 加密相关接口及模型格式受工具链和运行库支持条件约束。采用官方当前 release 可用功能，并确认 runtime 能加载对应模型；生产环境的密钥不应硬编码在开源仓库、日志或纯文本配置中。

**判断标准：** 先验证当前 SDK 是否支持，然后在测试模型上演练。

### 安全变更也要回归功能

加密后的模型要重新验证正确输入输出、返回码、错误密钥行为、内存及初始化时间。安全机制若破坏恢复或升级流程，也会带来可用性风险。

**判断标准：** 同一测试图的明文/加密模型输出应满足既定一致性标准。

## 故障排查

### 加密后模型加载失败

- 可能原因：runtime 不兼容、模型密钥或数据损坏。
- 验证动作：记录返回码、SDK 和模型生成历史。

### 加密仍能被复制

- 可能原因：未提供设备绑定或密钥管理。
- 验证动作：复查威胁模型与密钥分发方式。

## 案例研讨

**问题：** 将解密密钥硬编码到公开 C++ 程序中，是否就保护了模型？

**分析：** 不能将其作为充分保证。具备程序读取能力的攻击者可能找到硬编码密钥。需要合适的密钥管理和多层安全机制，并接受独立安全审查。

**证据：** 威胁模型、密钥管理设计、兼容性验证和回退方案。
