## 原理精讲

### 转换五阶段及返回码

创建 `RKNN` → `config` 配置平台和预处理 → `load_onnx` 加载计算图 → `build` 执行图优化与编译 → `export_rknn` 导出目标模型，最后 `release` 清理资源。所有步骤的返回码必须检查；示例路径需要替换成自己实际下载的模型。`target_platform='rk3588'` 对应目标 NPU，而非训练机器的 CPU。

**理解检测：** 能说明 config、load、build、export 的前后依赖关系，并知道在哪一阶段捕获异常。

### 非量化优先构建

第一次转换应先构建非 INT8 版本，用来验证算子、shape 与基本模型语义。启用 INT8 校准需要使用代表性图片列表或模型相关数据集；错误的校准样本可能导致严重精度损失。版本不同，参数和路径要求应以官方示例为准。

**理解检测：** 非量化是定位转换问题的对照组，不是声称永远优于 INT8。

### 数值一致性与部署验收

源框架、ONNX Runtime、RKNN 模拟器、RK3588 板端的数值路径可能有合理差异，但应采用同一图片、等价的预处理、相同输出后处理和可比的度量。分类比较 top-k 与 logits；检测需要比较 mAP、漏检和定位误差。只拿一张图片肉眼判断不够。

**理解检测：** 转换成功后必须做功能回归、性能评估、精度统计三个环节。

## 操作实验（需记录证据）

### 实验 1：检查 ONNX

用 onnx/checker 或 ONNX Runtime 读取模型输入输出，打印每个 tensor 的名称、维度、数据类型；记录 opset。

**验收方法：** 输入 shape 与实际输入预处理计划一致，模型语法检查通过。

### 实验 2：完成非量化转换

在匹配的 Toolkit2 环境创建 RKNN 对象，完成 config/load/build/export，并在 finally 中 release。

**验收方法：** 确认每步返回码成功且 .rknn 文件存在，附上 SHA256。

### 实验 3：设置对照基线

固定一个小型验证集，以同样预处理比较 ONNX 和 RKNN 的输出；再评估是否启动 INT8 校准。

**验收方法：** 记录数值差异、任务级精度和不一致的测试样本。

### 参考命令或代码

```python
from rknn.api import RKNN
rknn = RKNN(verbose=True)
try:
    assert rknn.config(target_platform='rk3588') == 0
    assert rknn.load_onnx(model='model.onnx') == 0
    assert rknn.build(do_quantization=False) == 0
    assert rknn.export_rknn('model.rknn') == 0
finally:
    rknn.release()
# 替换实际模型路径；mean/std 需要结合训练协议设置。
```

## 故障排查

### build 失败提示不支持算子

- **可能根因：** 源模型 opset 或图算子超出当前 Toolkit2 支持范围。
- **验证路径：** 定位日志中的算子名称及节点，参考官方 User Guide 重新导出或修改模型。

### 量化后准确率降低

- **可能根因：** 校准集范围或预处理参数不代表真实输入。
- **验证路径：** 先恢复非量化基线，检查训练/转换时的 mean、std 与颜色顺序。

## 案例研讨

**问题：** ONNX 能用 ONNX Runtime 预测正确，RKNN 导出成功但分类几乎随机。下一步直接换新模型吗？

**推理：** 先检查模型输入布局和数值范围：ONNX 常使用 NCHW float32，而 RKNN 可能配置了不同的 RGB、mean/std、dtype 路径。使用固定样本对比进入模型前的真实张量，再比较非量化输出，最后才进入校准阶段。

**交付证据：** 模型 shape、预处理参数、SDK 版本、同一图像在各阶段的 top-k 与输出差异。
