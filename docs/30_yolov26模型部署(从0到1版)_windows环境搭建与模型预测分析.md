## 核心知识精讲

### 训练环境先建立可复现的‘最小闭环’

在 Windows 进行 YOLO26 等检测模型实验，建议先配置受支持的 Python、PyTorch 与 Ultralytics 环境，确认 GPU 驱动/CUDA 是否与 torch wheel 匹配。CPU 也可完成小规模预测冒烟，但大型训练效率较低。将 YOLO 模型版本、包版本和权重来源固定到记录里，特别注意 YOLO26 对应的软件 release 是否支持该模型结构。

**你应该能解释：** 单图预测成功只证明训练框架的部分环境可用，不代表 RKNN 部署链路也已跑通。

### 理解预测输出

在训练框架中 `model.predict` 通常返回具有 boxes、scores、class id 的结果对象。要区分原框架输出与原始 ONNX tensor：Ultralytics 高层接口可能自动执行解码和 NMS，导出后的 ONNX 可能产生不同形式的原始预测。对每张图保留模型权重、置信度阈值、输入尺寸和版本，避免把可视化框当作唯一验证材料。

**你应该能解释：** 能从预测输出解释类别、置信度、xyxy 坐标以及坐标所属的图像空间。

### 跨平台部署不要跳级

训练环境在 Windows 不意味着 RKNN-Toolkit2 的模型转换必须在 Windows 上执行；应优先使用官方支持的 Linux x86_64 开发环境或经文档验证的 WSL。YOLO26 是否可通过当前 RKNN 编译器，需要先做 ONNX 算子兼容性和导出输出结构检查，不能仅凭 Ultralytics 支持 ONNX 就推断 Rockchip 已正式支持该检测头。

**你应该能解释：** 始终按 PyTorch → ONNX Runtime → RKNN → 真实 RK3588 的顺序定位问题。

## 跟做实验与交付物

### 实验 1：固定训练环境

安装官方文档支持的 Python/PyTorch/Ultralytics 组合并记录 `python -V`、torch 和 ultralytics 的包版本。

**验收证据：** 明确是 GPU 还是 CPU 推理环境，能重复导入软件。

### 实验 2：做单图预测

使用取得许可的 YOLO26n 权重和测试图，调用高层预测并打印 boxes.xyxy、conf、cls。

**验收证据：** 保存检测结果、模型权重来源、置信度设置和原图。

### 实验 3：冻结结果基线

为三张不同尺寸、场景的测试图建立 JSON 结果记录，并保存训练框架和模型版本。

**验收证据：** 下一步导出 ONNX 后有可对照的框、类别和分数。

### 参考实验片段

```python
from ultralytics import YOLO
model = YOLO('yolo26n.pt')  # 权重需按官方文档获取
results = model.predict(source='test.jpg', imgsz=640, conf=0.25)
for result in results:
    if result.boxes is not None:
        print(result.boxes.xyxy, result.boxes.conf, result.boxes.cls)
# 这是训练框架的高层预测，不是 RK3588 板端推理。
```

> 第30讲涉及的 YOLO26 → RKNN 流程需核对对应 SDK 的算子兼容性；并非官方已验证直接支持的承诺。训练权重与数据集需要自行按许可获取。

## 排查失败场景

### PyTorch 无法使用 CUDA

- 可能原因：显卡驱动、PyTorch CUDA 构建与设备能力不匹配。
- 验证方法：先验证 torch.cuda.is_available()，核对官方安装说明并保留 CPU 冒烟路径。

### 同样的图片预测框与教程不同

- 可能原因：权重版本、imgsz、conf、NMS 实现和 Ultralytics 版本不同。
- 验证方法：固定权重 hash、输入图片与全部推理参数。

## 综合案例分析

**问题：** Windows 下模型能推理，但装了新版本 Ultralytics 后检测框数量发生变化，是否意味着训练数据错了？

**推理过程：** 先调查升级导致的后处理阈值、默认参数或输出形式变化，恢复固定软件版本对照同样权重与图片。功能差异不一定来自数据本身。

**提交材料：** 权重 SHA256、软件版本、模型参数、同图预测 JSON 和可视化结果。
