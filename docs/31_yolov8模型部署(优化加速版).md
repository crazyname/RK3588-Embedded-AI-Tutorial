# 第31讲｜yolov8模型部署(优化加速版)

> 面向自学者的原创重编教材。建议按照原理→实验→数值回归→排障→自测的顺序操作。原视频转写在文末，仅供溯源。

## 学习目标

- 独立测量未优化版本的耗时
- 比较 INT8、线程池、算子改动和前处理方案
- 保证加速后检测精度与稳定性

## 核心知识精讲

### YOLOv8 的实际输出依赖部署版本

官方 RKNN Model Zoo 的 YOLOv8 转换示例采用针对 RKNN 适配过的输出结构，与上游原始 YOLOv8 模型输出可能不同。部分检测头输出将边框坐标和类别概率分开，解码可能包括分布式边框回归（DFL）等步骤。应使用相同 Model Zoo commit 的模型和后处理，避免换一个 ONNX 后沿用旧代码。

**你应该能解释：** 任何优化前先在 Netron 确认输出 shape、名称、量化属性和解码实现。

### 定位 端到端 FPS 的瓶颈

检测系统常包含相机、图像变换、NPU 推理、decode/NMS、绘图与显示。可优化的方向包括减少不必要拷贝、图像预处理硬件化、合理量化、更小的输入尺寸、合适的 NPU 核配置和高效后处理。每个因素有精度、算子支持和功耗代价，需要有控制变量实验。

**你应该能解释：** 给每项优化记录相同分辨率、相同数据集的 mAP、p95 延迟和 FPS。

### 不要把实验速度当成业务速度

Model Zoo 的 benchmark 可能只统计特定条件下的推理时间，不能直接代表你项目摄像头运行的端到端 FPS。短时间展示的高帧率还可能受热频率变化、输入缓存及计时范围影响。最终优化应以足够长的实际应用负载与独立验证集为依据。

**你应该能解释：** 对所有声称的‘加速倍率’给出基线、测量方法、持续时间和精度变化。

## 跟做实验与交付物

### 实验 1：复现官方 YOLOv8 baseline

按 Model Zoo 的 YOLOv8 README 在 RK3588 上完成配套转换/推理，保存输出图片与 tensor 信息。

**验收证据：** 得到对应版本的正确检测结果与完整日志。

### 实验 2：列出性能构成

为 resize、NPU、解码、NMS、绘图分别计时，记录 p50/p95 与温度。

**验收证据：** 能指出占用最高的阶段并提出假设。

### 实验 3：进行一次消融

只改一个因素，例如后处理实现或图片 resize 方案，其他条件固定，重新测精度和吞吐。

**验收证据：** 至少形成一行前后对照并解释收益和代价。

## 排查失败场景

### 切换模型后检测框全部错误

- 可能原因：采用了另一模型版本的输出布局或 DFL/后处理方法。
- 验证方法：打印输出 tensor 属性并与该版本 Model Zoo 对比。

### FPS 提升但小目标漏检

- 可能原因：输入变小或量化导致分辨率/精度损失。
- 验证方法：分组计算小目标召回率，检查 NMS 和置信度阈值。

## 综合案例分析

**问题：** 有人宣称 YOLOv8 在 RK3588 上优化到 150 FPS，但你的摄像头只显示 30 FPS。这个数据必然造假吗？

**推理过程：** 不能直接下结论。需要确认对方是否只计纯 NPU benchmark、使用更小的模型/分辨率或读内存中的固定图片，而摄像头端到端还受传感器帧率限制。只有同测量边界才可比较。

**提交材料：** 设备/模型/输入配置、分段时间、数据源和至少一次长时间运行日志。
