# 第19讲｜多Batch处理

> 利用批量推理理解多核 NPU 的吞吐能力。

## 学习目标

- 区别单样本时延和批量吞吐
- 了解 batch、上下文和多核调度之间的关系
- 测量批量输入的内存及性能开销

## 核心知识

多 Batch 将多个同类样本放入同一批次，有助于提升吞吐或利用多核，但不保证每张图片响应更快。SDK 可能通过上下文复制、运行时线程和多核调度分担工作。应区分“batch 维度变大”和“建立多个独立推理上下文”：它们的数据路径及调度方式可能不同。

## 实验与实践步骤

1. 检查模型与工具链允许的 batch 规格
2. 准备同尺寸、同通道布局的多张图片并组装输入
3. 分别测试 batch=1 和支持的多 batch 组合
4. 测量每批耗时、单图等效耗时、吞吐以及内存
5. 将结果与多线程/多上下文方案比较

## 验收标准

- [ ] 能解释批量吞吐提升不等于单请求延迟降低
- [ ] 能够测出 batch 增大后的内存开销

## 常见问题与注意事项

- 不同 RKNN 模型可能不支持期望的 batch 尺寸
- 三核 NPU 不意味着业务吞吐必然线性提升三倍

## 课后练习

1. 规划 batch=1/2/3 的精度与速度对照测试
