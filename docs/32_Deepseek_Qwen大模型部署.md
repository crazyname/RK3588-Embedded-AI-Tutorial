## 学习目标

- 了解 RKLLM 与 RKNN 图像模型工具链的区别
- 理解量化、内存和上下文长度对部署的影响
- 完成一组可复现的板端文本生成测试

## 核心知识

大语言模型在 Rockchip 平台可使用 RKLLM 相关工具链：获取被当前工具支持的原始权重，按 SDK 说明转换与量化为目标格式，再由板端运行时加载模型进行文本生成。这里的文件格式、运行时与图像分类/检测所用 RKNN API 不是一回事。选型应核对所需内存、KV cache、上下文长度、模型许可、实际 tokens/s 和首 token 延迟。

## 实践步骤

1. 确认 RK3588 的内存容量、板端运行时与驱动
2. 从官方支持矩阵选择可在目标硬件上运行的 Qwen/DeepSeek 具体版本
3. 获取有合法使用许可的模型权重并记录来源与版本
4. 按对应 RKLLM SDK 文档执行转换与量化
5. 部署模型和配套运行时，检查内存、加载时间及运行日志
6. 执行中文问答、连续对话和常识问题，记录首 token 延迟与 tokens/s
7. 对比不同量化参数和上下文窗口对性能的影响

## 完成标准

- [ ] 板端可以完成至少一轮文本生成
- [ ] 能够报告模型完整名称、量化类型和运行时版本

## 常见问题与注意事项

- 不是所有 Qwen/DeepSeek 规模和版本都支持 RK3588
- 上下文增长会增加 KV cache 占用并影响推理效率
- 生成看似流畅不等于回答事实正确

## 课后练习
