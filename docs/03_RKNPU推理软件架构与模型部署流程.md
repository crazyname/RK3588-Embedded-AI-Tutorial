## 技术原理精讲

### 转换与运行是两个环境

RKNN-Toolkit2 常在开发主机上读取 ONNX 等模型，执行图优化、编译与可选量化，再导出面向目标芯片的 .rknn。RKNN Runtime/Lite2 则在板端加载该文件，调用 RKNPU 驱动执行。主机工具不是板端驱动，板端运行时也不能简单代替主机模型转换。

**判断是否理解：** 画清楚训练框架、ONNX、Toolkit2、.rknn、Runtime、kernel driver 之间的边界。

### 版本协作链

一份模型由某个 Toolkit2 版本生成，目标板拥有特定版本的 librknnrt 和内核驱动。不同代 SDK 的格式及接口可能存在兼容条件；‘某篇教程可以运行’不代表你当前板子也能运行。应以官方发布的支持关系和实际 log 为准，同时保存 wheel 版本、runtime 版本与固件版本。

**判断是否理解：** 排查模型加载失败时，优先记录所有版本，再考虑是否需要升级；禁止跳过备份直接刷写。

### 理解前后处理的职责

图像从摄像头进入后还可能经过裁剪、缩放、letterbox、通道交换与标准化。模型输出的往往是 tensor，不一定是画好的检测框；分类需标签映射，检测需 box decode 和 NMS。软件框架只负责其中一段，应用正确性依赖前后处理与模型的训练约定一致。

**判断是否理解：** 可以用可重复的输入对源模型、ONNX 和 RKNN 三阶段做结果比对。

## 故障诊断

### 模型无法初始化

- 可能原因：转换与运行组件之间可能不兼容，也可能是文件损坏或目标 SoC 配置错误。
- 诊断动作：记录详细返回码、Runtime/Driver 版本及 .rknn 创建来源。

### 可加载但结果错乱

- 可能原因：前处理或输出张量属性不一致，不能仅据此断言驱动损坏。
- 诊断动作：查询 shape、layout、dtype、量化 scale/zp，再逐阶段比对数值。

## 自学案例分析

**情境：** 模型在电脑模拟器上预测正确，但拷到 RK3588 后提示版本不匹配。应该先换芯片还是更新运行库？

**分析路径：** 先确定版本链：工具链版本、模型目标平台、板端 runtime/driver 和 BSP。参考官方兼容指南制定升级或重新转换策略。不能只因为模型能在 PC 上跑，就认为任何旧固件都能加载。

**应交付证据：** 模型来源、目标参数、版本号、完整错误码和更改前后的对照日志。

## 源码精读：关键 API、张量与验收

部署不是一个“执行转换”按钮，而是模型、转换器、运行库、输入协议与指标的有向依赖链。lesson_03.py 能根据真实完成状态生成 Graphviz DOT 并列出尚未完成的阶段。

**数据路径：** `ONNX 图检查` → `RKNN Toolkit2 转换` → `Driver/Runtime` → `预处理协议` → `实际推理` → `精度验收`。

### 1. STAGES：明确各部署阶段责任

**输入：** 六个阶段 onnx/convert/runtime/input/inference/accuracy。**输出：** 每一阶段的输入产物与可观察验收点。

主机转换和目标板执行发生在不同环境，不能在转换阶段失败时先假定是 NPU 驱动问题。完整流程中“程序能跑”也不能替代任务精度合格。

```bash
python3 examples/lesson_03.py --dot build/lesson03/pipeline.dot
```

### 2. --status：用布尔事实标记进展

**输入：** 可选 JSON 映射，如 {'onnx':true,'convert':false}。**输出：** completed 和 remaining 两组阶段。

脚本不联网也不运行 SDK；它只把已经实测的状态画成图。未提供的阶段默认未完成，不能因文件存在就自动勾选为成功。

```bash
printf '{"onnx":true,"convert":false}' > /tmp/rknn_status.json
python3 examples/lesson_03.py --status /tmp/rknn_status.json --dot build/lesson03/pipeline.dot
```

### 3. DOT 文件：将流程可视化并定位失败位置

**输入：** 有向依赖与完成状态。**输出：** 可由 Graphviz 转成 PNG 的流程图。

绿框代表手动给出的已完成状态，不是 GitHub CI 对硬件自动验证的结论；图中每条箭头是模型与数据协议的依赖关系。

```python
dot -Tpng build/lesson03/pipeline.dot -o build/lesson03/pipeline.png
```

**数据例题：** 若 ONNX 与转换已完成，但 Runtime/驱动未确认，则部署图依然包含未完成阶段，不能把这个 RKNN 文件视为在 ROCK 5B 上已能推理。

**验收边界：** 交一张有六阶段的依赖图，并给出每一项需要的实际证据、PC/板端工作归属与下一步实验。
