## 学习目标

## 原理精讲

### 频率变化和 DVFS

CPU、NPU 与 DDR 可能通过 DVFS（动态电压频率调整）策略在不同负载和温度下改变频率。设备树与内核 governor 决定支持哪些频点，路径因 BSP 而异。强制定频并不等于软件不会降频，因为热保护、电源能力和系统策略仍可能生效。

**理解检测：** 先读出当前 governor、可用频点和温度，变更之前保存原值。

### 为什么测试必须热稳定

持续负载会让芯片温度上升，可能触发降频。第一次运行还可能包含模型初始化和缓存预热，因此单次最快耗时通常不能反映长期表现。测试要固定分辨率、模型、输入顺序、板端后台任务及测量时长，分别记录 warm-up 与稳定阶段。

**理解检测：** 报告平均值、至少一个尾延迟指标和温度区间，比只报最大 FPS 更可信。

### 功耗与速度的取舍

提升 CPU/NPU/DDR 频率可能缩短部分阶段耗时，但也可能提升发热与能耗。若应用主要瓶颈是 NMS 或输入复制，仅提高 NPU 频率收益有限。应先对端到端管线逐段计时，再选影响最大的资源进行控制变量实验。

**理解检测：** 不要同时改三个频率；否则即使 FPS 上升，也无法解释是哪一项产生效果。

## 操作实验（需记录证据）

### 实验 1：建立无侵入基线

在不改频的条件下使用固定输入测试多次，记录 CPU/NPU/DDR 当前频率（若 BSP 暴露只读节点）及温度。

**验收方法：** 输出时间序列包含空载与负载各一个阶段，不是只有一个瞬间值。

### 实验 2：寻找可用接口

根据具体 BSP 查阅 `/sys/class/devfreq` 与 cpufreq 可读项。不同发行版可能不公开 NPU 节点，不要猜路径。

**验收方法：** 记录存在的目录与其 governor/频率，不存在则注明‘此 BSP 未暴露’。

### 实验 3：做单变量分析

只有在确定允许操作且做好回退时，修改一个受支持的 governor，再重复完全相同的工作负载。

**验收方法：** 形成条件、频率、温度、延迟与功耗（若可测）的对照表。

## 故障排查

### 强制定频后仍然降速

- **可能根因：** 散热不足、系统功耗约束或频率设置被其他服务覆盖。
- **验证路径：** 同步记录温度和频率曲线，查看节流及 governor 状态。

### 频率节点不存在

- **可能根因：** 教程示例对应的内核/BSP 与当前设备不同。
- **验证路径：** 以设备树、驱动和 `/sys` 实际只读结果为准，不按教程硬写不存在的节点。

## 案例研讨

**问题：** CPU 频率设高后，短跑 30 秒提速，连续运行 15 分钟却变慢。怎样解释？

**推理：** 先查看温度及频率随时间变化，排除热节流；再确认输入、模型和背景负载一致。高频率可能导致更快升温，最终进入更低可持续频点。

**交付证据：** 按分钟记录温度、频率、p50/p95 延迟和 FPS 的时间序列表。

## 工程机理与知识深化

### 系统机制与数据协议

DVFS 让 CPU、NPU 与 DDR 在负载、温度和功率限制下改变频率。推理瓶颈可能在 NPU 算子，也可能在摄像头采集、CPU letterbox、内存传输或后处理；单纯提高 NPU 时钟只能影响受 NPU 算力限制的部分。采样频率与温度需要记录节点名称、单位和时刻，不能脱离采样窗口分析。

### 具体算例与故障现场

同一模型的 NPU 耗时为 4ms、CPU 前后处理共 16ms，串行总时延约 20ms，即 50FPS；即使 NPU 降为 2ms，总时延仍约 18ms、约 55.6FPS。若温度升高触发降频，短时首帧数据也不代表稳定运行性能。

### 设计选择与验收判据

只读监测是第一阶段。对比时固定图像、模型、线程数、NPU 核配置与运行区间，至少保存延迟分布和相应的频率/温度原始记录；不直接修改未知 sysfs 节点。

**数据路径：** `Linux sysfs 可用节点` → `CPU/NPU/DDR 频率与温度` → `多次只读采样` → `frequency.csv` → `与真实推理耗时对照`。

### 1. nodes()：发现 sysfs 而非猜测路径

**输入：** /sys/devices/system/cpu、/sys/class/devfreq、/sys/class/thermal。**输出：** 可读取的 cur_freq、scaling_cur_freq、temp 节点列表。

不同板商 BSP 可能有不同设备路径，也可能因为权限不允许读取。路径名字不能保证全都对应 NPU；看到数值应先判断单位和设备。


**输入：** 每次 sysfs 读取的原始字符串与 Unix 时间。**输出：** unix_time、sysfs_path、raw_value。

CPU/DDR/NPU 频率通常以 kHz 或驱动定义单位表示；温度节点一般是毫摄氏度，展示前要先确认来源。

