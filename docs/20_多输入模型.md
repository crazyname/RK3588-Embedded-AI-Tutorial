## 从原理到工程

### 多输入模型的定义

多输入是计算图拥有两个或更多彼此独立的输入节点，例如图像特征和标量传感器信息，或双图像视角。每个输入分别有 dtype、shape、format、量化属性和语义。与 batch 的‘一个输入里叠加多个样本’不同，多输入模型可能包含异构数据，必须按官方 tensor index 一一绑定。

**必须理解：** 能在 Netron 找到 input 名称和顺序，避免只用数组长度推断。

### 输入融合的语义与时间同步

图像与 IMU 或温度传感器融合时，网络要求的往往是同一事件时刻的数据。如果图像来自 t=0，而传感器采样来自 t=2s，就算程序接口没有报错，输出语义也可能错误。前处理还要保证不同输入数值范围与训练时一致。

**必须理解：** 为每个输入记录采样时间、量纲、归一化、dtype 和 shape。

### 部署时的输入属性检查

加载模型后查询输入数量和各 tensor 属性，再逐个设置数据。C API 的 `rknn_inputs_set` 输入数组中的 index 与实际模型输入对应关系要明确；使用 Lite2 也需确认传入 list 的顺序。量化输入不能直接用错误的字节数或数据类型覆盖。

**必须理解：** 模型接受数据不等于输入语义正确，必须使用成对验证样本对比输出。

## 典型报错与诊断

### 双输入被误认为一个 Batch

- 可能原因：输入节点数与输入张量第一维概念混淆。
- 定位方法：读取模型实际的 graph.input / rknn_query 数量。

### 运行正常但融合预测很差

- 可能原因：输入数据单位不一致或传感器与图像不同步。
- 定位方法：打印每个 tensor 的值域、dtype、时间戳。

## 案例演练

**问题：** 两个摄像头模型分别接左图和右图，程序写反输入顺序却没有报错，怎样发现？

**思路：** 如果两个 tensor shape 完全相同，类型检查不一定能发现语义交换。应通过同一对已知场景图验证输出，并给输入 index 建立显式名称映射。

**作业证据：** 输入节点清单、配对图片标识及不同顺序的输出对照。
