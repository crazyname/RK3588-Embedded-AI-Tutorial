# RK3588 嵌入式 AI HTML 教学规划

课程目标：从 RK3588 体系结构出发，掌握 RKNN 环境、模型转换、精度/性能/内存分析、C/C++ API、YOLO 项目及 RKLLM 大模型的板端部署。

## 课件阅读方式

**每节课只是一整篇连续的 HTML 教学长文**：所有课程章节按顺序自上而下展开；左侧目录可点击跳转锚点，阅读进度随滚动位置更新。互动选择题和验收清单在原位置直接使用，打印为整篇文稿，而非逐张幻灯片。

## 授课方法

课堂按场景导入（10%）、理论与架构（30%）、教师示范及学员实践（40%）、错误诊断与互动问答（10%）、学习验收与作业（10%）安排。理论课可用结构图推演代替真实上机。

## 考核方式

- 概念理解 20%：CPU/NPU/模型格式/软件架构。
- 环境可复现 25%：版本、配置、日志和真实输出。
- 精度与性能 25%：转换、量化、时延、内存记录。
- 工程实践 20%：C/C++、资源管理、检测后处理。
- 综合报告 10%：对照实验、问题复盘和演示。

## 教学环境

需要 RK3588 开发板（具备配套固件）、供电与散热、串口或网络连接、x86_64 Linux 主机、对应版本 Python/Conda 与 C/C++ SDK。Windows 模型训练课程需额外准备训练主机环境。

课件内容源于本仓库 Markdown 讲义与原始视频口播，部分演示设计和课堂测验为教学性补充。仓库未包含视频中的全部源码、模型和数据集；所有操作应核对当前 SDK 与硬件说明，尤其是刷写固件及定频。

## 各单元教学重点

**基础认知**：不是要求背诵参数，而是要求学生能画出 RK3588 的 CPU/NPU/RGA/DDR 分工及一份模型从主机转换到设备推理的软件链路。验收重点是结构解释与适用场景判断。

**环境搭建与入门**：强调 ABI/架构、操作系统、Python、SDK、驱动与 runtime 的匹配关系。教师应预先准备一套已知可工作的环境；当学生设备差异大时，不建议现场盲目刷写系统。

**模型转换与优化**：每组必须记录浮点参考模型、未量化 RKNN 与 INT8 RKNN 的测试输入和结果。性能对比需要明确测试条件、量化配置、输入 shape 与温度频率等参数。

**高级 API 与工程化**：重点是 C/C++ 资源生命周期、输入输出 tensor 属性、缓冲区所有权、缓存一致性及错误处理。零拷贝与多核优化必须以端到端实测为结论依据。

**项目实战与大模型**：从 MobileNet 形成最小应用，过渡到 YOLOv5 的检测后处理与工程封装，再完成检测模型训练/转换/部署和性能优化。RKLLM 部分以模型支持矩阵、内存约束和真实生成速率为核心，不盲目追求最大参数量。

## 综合实训与成果评审

推荐最终课题为 **RK3588 实时安全帽目标检测系统**；也可选择人脸检测、垃圾分类或零部件检测。验收需要至少包含：

1. 架构和数据流图：说明采集、预处理、NPU、后处理及显示阶段。
2. 模型来源和数据协议：权重许可、数据集与类别映射、输入 shape、dtype、归一化策略。
3. 模型转换证明：源框架、ONNX、RKNN 三个阶段的有效输入输出和版本记录。
4. C/C++ 程序：初始化、推理、资源释放、错误码与独立可复用的前后处理模块。
5. 量化与性能评价：至少一个任务级精度指标，以及 NPU 时延、总延迟、FPS 和内存记录。
6. 优化与排错报告：基线、每次修改的变量、观察结果、预期差异及失败记录。
7. 现场演示与答辩：解释误报漏报、坐标变换、资源瓶颈和可改进方案。

**教师准备建议：** 每个实操讲次准备一个“已验证的基线工程”和一个“故意引入的错误案例”，例如错误通道次序、错误 shape、旧 runtime、遗漏资源释放或错误的 letterbox 坐标还原，以便在真实设备缺失时仍能开展针对性的诊断练习。
