# 课程源码的验收标准

程序文件存在、入口 --help 可执行、CI 成功，这三项都不能单独证明课程工程完成。需要按功能和硬件条件验收。

## 每讲至少包含的交付物

1. lesson_NN.py：真正实现课程目标。可复用共享算法，但禁止只用课号转发函数或硬编码虚构推理结果。
2. 最小测试输入：可重复的算例、真实 ONNX、许可合规图片或明确标注的模拟数据。
3. 功能测试：至少测试一次正常路径和一次错误输入路径；计算结果需要数值断言，不只是 --help。
4. 简明运行手册：examples/notes/lesson_NN.md 只描述环境、命令、输入输出、预期结果和排障；原理解释继续放 docs/，避免同一内容重复。
5. 验收记录：CI 结果、SDK/驱动版本、模型哈希、板端真实输出，以及不能完成的原因。

## 三层结果必须分开

| 层次 | 判断标准 |
|---|---|
| PC/CI | 数学、ONNX Runtime、数据处理或文件生成在无板卡环境中实际执行，输出符合断言 |
| SDK | 真实转换/Runtime API 与某个固定 release 及模型文件兼容 |
| ROCK 5B/RK3588 | 真实 NPU 或外设执行，保存实际结果、日志、温度、时延与硬件版本 |

## 当前最容易出现误判的课程

- 第18讲 Fernet 文件加密不是 RKNN 原生模型加密，密文不能直接交给 RKNN Runtime。
- 第23讲生成 C++ 张量声明不等于生成了完整的推理代码。
- 第26讲仅核对 stride/字节数不等于实现零拷贝，需要实际创建/绑定 I/O buffer、缓存同步与对照测试。
- 第29/33讲 YOLO 必须有配套版本的输出解码、letterbox、NMS 和真实检测图片。
- 第30–32讲 ONNX 导出成功不意味着 YOLO26 能编译成 RKNN 或在 RK3588 成功推理。
- 第34讲 RKLLM 权重大小推算不等于设备真实生成与 tokens/s 记录。

## 随时查看即时状态

在仓库根目录运行：

    python3 examples/audit_course.py

在全部替换完毕之后运行：

    python3 examples/audit_course.py --strict

此检查仅识别文件结构与薄入口、缺失说明。无论结构检查多完整，都不能代替运行真实硬件与任务级精度验收。
